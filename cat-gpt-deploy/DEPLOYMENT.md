# Cat GPT — Free Deployment Guide ($0, no credit card)

**Stack:** GitHub (code) → Render free tier (FastAPI backend) + Vercel Hobby (Next.js frontend)
**External services:** Groq API (LLM), Hugging Face Inference Providers (image generation; set `HF_API_KEY`), Hugging Face embeddings (local)

---

## ⚠️ Read first: what resets on the free tier

Render's free disk is **ephemeral**. On every new deploy/restart these are wiped:

- All 3 SQLite databases (`database/db.py` chat/memory, `api/store.py` auth/threads, LangGraph checkpoint store)
- Uploaded documents, generated images, media directories
- The FAISS index (rebuilt on next ingestion)

Sleep/wake between deploys keeps data intact. This is fine for a **portfolio demo** — just don't demo immediately after pushing a new commit. Permanent fix later = migrate to Neon free Postgres (see §9).

## 1. Confirm the deployment configuration

This repository already contains the deployment files. The root
`render.yaml` defines the backend service; `cat-gpt-deploy/render.yaml` is a
reference copy. Deploy the existing repository rather than copying or
reinitializing it.

| File | Current location or use |
|---|---|
| `render.yaml` | Already present at the repository root |
| `runtime.txt` | Already present at the repository root |
| `.gitignore` | Already present; preserve existing rules |
| `.env.example` | Already present at the repository root |
| `frontend.env.local.example` | Copy to `forntend/.env.local` for local development |

> Keep the directory name `forntend` as-is — the deployment config uses that exact spelling.

## 2. Before pushing (2 minutes)

**a) Python version** — Render defaults to an old Python unless you specify. Run locally:

```bash
python --version
```

Edit `runtime.txt` to match exactly, e.g. `python-3.11.9`.

**b) requirements.txt** — install from the committed file. Do not regenerate or
overwrite it as part of deployment unless you intentionally changed and
verified the project dependencies:

```bash
pip install -r requirements.txt
```

**c) Confirm environment variable names** — use the names in the root
`.env.example` and `render.yaml`; these are aligned with the current backend:

```bash
rg "os\.getenv|os\.environ" api agent rag database
```

The current configuration uses `GROQ_API_KEY`, `SESSION_SECRET`,
`GOOGLE_CLIENT_ID`, and `FRONTEND_ORIGIN` (not `SECRET_KEY` or
`CORS_ORIGINS`).

**d) Health route** — your API already keeps auth/health routes public. Confirm a `GET /health` exists in `api/main.py`; if not, add:

```python
@app.get("/health")
async def health():
    return {"status": "ok"}
```

**e) Check that secrets and runtime data are not tracked.** The existing
`.gitignore` excludes local environment files, SQLite databases, and `data/`.
Inspect the tracked-file list before changing ignore rules:

```bash
git ls-files "*.db" "*.sqlite" ".env" ".env.*"
```

## 3. Push the repository to GitHub

One repo containing `api/`, `agent/`, `rag/`, `database/`, and `forntend/`
works: Vercel uses `forntend/` as its root directory, while Render runs the
backend from the repository root. Use the existing Git repository and normal
branch/remote workflow; do not run `git init` again.

Confirm the existing repository points to the intended GitHub remote and
deploy the branch configured for the Render and Vercel services. Do not
reinitialize the repository or replace its remotes as part of deployment.

## 4. Backend → Render (free)

1. Sign up at [render.com](https://render.com) with GitHub (no card).
2. **New → Blueprint** → connect the `cat-gpt` repo. Render reads `render.yaml` and creates the service automatically.
3. Configure the environment values requested by the Blueprint:
   - `GROQ_API_KEY` → from console.groq.com
   - `GOOGLE_CLIENT_ID` → from Google Cloud Console (§6)
   - `FRONTEND_ORIGIN` → `http://localhost:3000,https://<your-app>.vercel.app`
   - `SESSION_SECRET` → generated by the Blueprint
4. Deploy. When live, note your URL: `https://cat-gpt-api.onrender.com`
5. Test: open `https://cat-gpt-api.onrender.com/health` and `/docs`.

*Manual alternative (if you skip the blueprint):* New → Web Service → root of repo → Build: `pip install -r requirements.txt` → Start: `uvicorn api.main:app --host 0.0.0.0 --port $PORT`.

## 5. Frontend → Vercel (free)

1. [vercel.com](https://vercel.com) → **Add New → Project** → import the same repo.
2. **Root Directory: `forntend`** ← important (typed exactly like that).
3. Framework auto-detects Next.js. Build defaults are fine.
4. Environment variable: `NEXT_PUBLIC_API_URL` = `https://cat-gpt-api.onrender.com`
5. Deploy → you get `https://cat-gpt.vercel.app` (rename as you like).

## 6. Google Sign-In setup

Google Identity Services checks the browser origin, so your Vercel URL must be registered:

1. Google Cloud Console → **APIs & Services → Credentials** → your OAuth 2.0 Client.
2. **Authorized JavaScript origins** — add:
   - `http://localhost:3000`
   - `https://<your-app>.vercel.app`
3. Save (takes ~1–5 min to propagate). If you use a redirect-based flow instead of GIS one-tap/button, also add the backend callback URL under *Authorized redirect URIs*.

## 7. CORS

`FRONTEND_ORIGIN` on Render must include your Vercel URL (set in §4). Separate
multiple origins with commas, for example
`http://localhost:3000,https://cat-gpt.vercel.app`.

## 8. Keep it awake (optional, recommended for demos)

Render free sleeps after 15 min idle (~40 s cold start + model load). To keep Cat GPT warm:

1. [uptimerobot.com](https://uptimerobot.com) (free) → Add New Monitor → HTTP
2. URL: `https://cat-gpt-api.onrender.com/health` — check every 10 minutes.

24/7 awake ≈ 744 hrs, inside Render's 750 free hrs/month.

## 9. Free-tier realities for Cat GPT specifically

| Concern | Impact | Notes |
|---|---|---|
| **512 MB RAM / 0.1 CPU** | HF embedding model + FAISS live in RAM | Use a small embedding model (e.g. `all-MiniLM-L6-v2`, ~90 MB). If logs show the process killed (OOM), that's the fix or a $7 upgrade. |
| **Cold start after sleep** | First request slow (~40 s + model load) | Keep-awake ping (§8) avoids it |
| **Model download** | Embedding model downloads on first run after each deploy | Slow first ingest after a fresh deploy |
| **Groq free rate limits** | Occasional 429s | Your model-fallback logic already handles this |
| **Hugging Face image generation** | External, requires `HF_API_KEY` | Uses FLUX.1-dev with a FLUX.1-schnell fallback |
| **Streaming (SSE)** | Works fine on Render | Event format/thread association untouched |

## 10. Later upgrades (when it's more than a portfolio)

1. **Neon free Postgres** (no card): replace the 3 SQLite stores — `api/store.py` and `database/db.py` (swap `sqlite3` → `psycopg`), and the LangGraph checkpoint store (swap `langgraph-checkpoint-sqlite` → `langgraph-checkpoint-postgres`). Data then survives deploys.
2. **Cloudflare R2 free tier** for uploaded files / generated images so media survives too.
3. Custom domains (free on both Vercel and Render).
